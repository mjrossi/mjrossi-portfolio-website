# File map

Every file in this repo that carries a decision, and the reasoning behind it. Split out of `CLAUDE.md` so the root file stays loadable; the root keeps a one-line index pointing here.

**Read this before editing anything under `src/lib/`, `src/components/`, `scripts/`, or `migrations/`.** Most entries record a bug that has already happened once, and the rule that stops it happening again — the kind of thing that looks like dead weight right up until you delete it.

For the preview-link clock-and-cap model, the galley, and the Desk, the narrative lives elsewhere: see [PREVIEW-LINKS.md](PREVIEW-LINKS.md), [GALLEY.md](GALLEY.md), and `CLAUDE.md` ("The Desk").

- `src/layouts/Base.astro` — shared shell. Renders the full Broadsheet masthead on every page, with the name as an `<h1>` on `/` and as a link back to `/` on subpages. Builds the edition line at request time so it stays current without a scheduled rebuild. Also takes `ogImage` / `ogImageAlt` so a post can carry its own social card.

- `src/components/ContactLinks.astro` — inline-SVG icon row (GitHub, LinkedIn, `/api/contact` email, Bluesky). Rendered twice per page (nav + footer); the smoke tests assert both occurrences.

- `src/components/BlogPostEntry.astro` — shared `<article class="post-entry">` card used by `blog/index.astro` and `blog/tag/[tag].astro`. Carries **no chip row**: five or six saturated chips per entry were the first thing the eye landed on, ahead of the titles, so up to two topics moved into the meta line (`PostTopics.astro`) and the full set lives on the post itself.
- `src/components/Figure.astro` — `<figure>` wrapper around `astro:assets` `<Image>` with an optional `<figcaption>`. Imported in `.mdx` posts when an inline image needs a visible caption separate from its `alt`.
- `src/components/diagrams/*.astro` — per-post explanatory diagrams as hand-authored **inline SVG**. Not site chrome; each is imported by exactly one `.mdx` post. Hand-authored rather than generated because the no-client-JS rule plus `script-src 'self'` rules out running mermaid in the browser, and pre-rendering it would mean a Puppeteer dev dependency and a house style that fights the Broadsheet palette. They emit their own `<figure class="post-figure post-diagram">` and reuse the existing `.post-figure` / `figcaption` rules — they do **not** go through `Figure.astro`, which requires `ImageMetadata`. Shared styling (`.post-diagram`, `.dg-*`) lives in `global.css`. See "Diagrams in posts" under Blog.
- `src/components/Subscribe.astro` — the email signup, in **both** of its placements, one form implementation behind a `variant` prop. `line` is a one-row accent band under the blog index header (the only accent-band element on that page, which is what earns it the saturation); `card` is a tonal `--bg2` card at the foot of every **published** post, deliberately quieter than the previous/next link below it. Replaces `NewsletterSignup.astro`, whose single bottom-of-index block outweighed the archive it belonged to. Loads Cloudflare Turnstile + the external submit handler, and owns its own scoped `<style>` block. **This is the first of two carve-outs from the no-client-JS rule and it is now wider than `/blog`** — placement `card` puts Turnstile and `/scripts/newsletter.js` on every published post. What has not changed: it is absent from every non-blog route, absent from a post rendered as a draft (so a galley reader never meets it), and must never be lifted into `Base.astro` or shared chrome. Smoke asserts the band on `/blog`, the card on a post, and the form's absence on `/`. In the band Turnstile runs `data-appearance="interaction-only"` — it still executes and still produces the token the endpoint verifies, it just doesn't draw itself unless a challenge is actually needed, because a one-line band has no room for a widget.
- `src/components/PostTopics.astro` — the post's topics, inline in a post's or an entry's meta line. **Up to two, in frontmatter order** (`TOPIC_LIMIT`; smoke asserts the rendered cap on a real post, so raising it is a decision rather than a drift). One was the original spec and it under-described: the Netherlands post is cycling *and* infrastructure *and* personal, and "Cycling" alone is true but thin. The ordering in frontmatter is the only signal available, and it carries a second job beyond specificity — it is what makes a series read as a series, which is why all three Atlas posts lead `urbanist-atlas` rather than each leading with its own most-specific tag.
- `src/components/PostNav.astro` — previous/next by publication date, below the tag footer and the subscribe card. No related-post logic. **A missing neighbour renders nothing** — no cell, no placeholder — and both missing renders no nav at all. It used to fill the empty end with "Newest post" / "Oldest post" in muted type, to avoid a one-column nav sitting in a two-column grid; that read as a broken link rather than as an end-of-archive marker, because under the `NEXT →` key the placeholder looks like the next post's *title* in a cell that carries a link on every other post. The layout half is CSS's job instead: `.post-nav` uses `grid-auto-flow: column` over `grid-auto-columns: 1fr`, so a lone cell fills the row and two split it, with no modifier class to keep in sync. **A draft renders no nav at all**, whatever its neighbours — `BlogPost.astro` drops previous/next together with the subscribe card behind the same `!scheduled` gate, on the argument that the post is not in the sequence yet. Undocumented until it broke a smoke check that assumed the newest real post is published; see `src/lib/archive.js`.
- `src/components/PageHeader.astro` — shared interior-page header (`<h1>` + optional description + default slot for `.page-meta`). Used by `/work`, `/education`, `/urban-mobility`, `/privacy`, `/blog/tags`, and `/blog/tag/[tag]`. `/blog` keeps its custom `.blog-header` since the RSS-link variant doesn't fit the prop shape.
- `src/components/PostTags.astro` — the chip list, rendered **once** by `BlogPost.astro` now, in the footer under a `label` ("Filed under"). The header copy was dropped: six chips between the title and the first word of prose were doing discovery work at the moment the reader wanted to start reading, and they were repeated verbatim below. Chips display a title-cased label via `tagLabel` and keep the kebab slug in the URL.
- `src/pages/*.astro` — one file per route. Public pages: `/` (About + Now + "From the Lexicon"), `/work`, `/projects`, `/education`, `/urban-mobility`, `/blog`, `/blog/tags`, `/privacy`, `/404`. Plus `/admin` and `/admin/<slug>` — the Desk, which is Access-gated and excluded from the sitemap. Output mode is `server`, so every page runs on-demand by default; only `/404` opts back into static via `export const prerender = true` (`/blog/rss.xml` renders on-demand so scheduled posts surface without a rebuild). `Cache-Control: public, max-age=3600` is applied centrally by `src/middleware.ts`, not per-page.
- `src/pages/api/contact.ts` — on-demand redirect. `GET /api/contact` returns 302 to `mailto:hello@mjrossi.com` so the address never appears in static HTML. Cloudflare's `_redirects` rejects `mailto:` destinations and the deploy is a Worker with Static Assets (not classic Pages), so `functions/` is unavailable.
- `src/pages/api/subscribe.ts` — on-demand POST endpoint. Receives `{ email, turnstileToken, company }` from the newsletter form, verifies the Turnstile token, forwards to Buttondown (default double-opt-in; passes `ip_address` so Buttondown's firewall can geo/reputation-score the request and avoid false-positive blocks). Treats already-subscribed as success to avoid leaking the subscriber list; surfaces other Buttondown 400s as `upstream_rejected` so the client falls back to the "email me to add you manually" message. Uses helpers from `src/lib/server.ts`.
- `src/pages/admin/index.astro`, `src/pages/admin/[slug].astro` — **the Desk**: the read-only operator surface, gated on Cloudflare Access in `src/middleware.ts`. Zero client JS, which is what keeps it clear of the site-wide `script-src 'self'` / `form-action 'none'` CSP entirely. See "The Desk" under Blog.
- `src/layouts/Desk.astro` — the Desk's chrome and **all** of its CSS. In this file rather than `global.css` for the reason `GalleyMargin.astro` keeps its own block: `global.css` ships on every public page, and Astro decides what a stylesheet contains from the module graph, so rules put there would be weight on every reader for markup none of them can see. Only the `/admin` routes import this, so its styles end up inlined in the server bundle and there is no client stylesheet to leak. `is:global` rather than scoped — unlike the galley's `is:inline`, which was about elements created at runtime — because the markup is rendered by the *page*, in the page's own scope, and scoped rules written here would not match it. Smoke asserts this **twice, and both halves are needed**: no `desk-` identifier in a public page's HTML, and no `desk-` in the built CSS bundle. A stylesheet hoisted into a public route appears in that page's HTML only as a `<link href="/_astro/….css">` and carries no `desk-` substring at all, so the HTML check alone would stay green while every reader paid for the operator chrome — which is exactly how the galley bug shipped.
- `src/lib/access.js` — Cloudflare Access JWT verification: JWKS fetch (memoised with a TTL), RS256 via `crypto.subtle`, then `exp` / `nbf` / `iss` / **`aud`**. The audience check is the load-bearing one — Access signs per *team*, so a token from any other app on the account verifies otherwise. `alg` is pinned rather than read from the token. Fails closed on every branch including missing config. `ACCESS_JWKS_OVERRIDE` replaces the fetch for local work and smoke, and must never be set in production. Unit-tested in `src/lib/access.test.js`.
- `src/lib/admin-path.js` — `isAdminPath(pathname)`, shared by `src/middleware.ts` and the sitemap filter in `astro.config.mjs`. One function because **three** things must agree on the answer, the third being the Access app's path pattern, and because a bare `startsWith('/admin')` also matches `/administrator`.
- `src/lib/desk.js` — `deskIndex(...)`, what earns a row on the Desk index and in what order. A **union**, not a filter over the collection: a round can outlive its draft and a link can outlive its post entirely. Also `countdown(pubDate, now)`, which counts **calendar days in UTC, not elapsed time** — ceiling the millisecond gap read the last day of every schedule wrong in both directions (thirty minutes out said "tomorrow", twenty-five hours out said "in 2 days"), and that is the deadline `deskIndex` sorts every row by. Here rather than in the page because it is a decision whose failure is a plausible wrong number, and `node --test` cannot reach an `.astro` file. Unit-tested in `src/lib/desk.test.js`.
- `src/lib/links-store.js`, `src/lib/notes-store.js` — every statement against `preview_links` and `galley_notes`, written once in D1 idiom against a duck-typed store (the `isLinkActive(DB, id)` pattern). The worker passes its binding; the CLI passes `scripts/d1-store.mjs`. The shape checks in them are **domain validation, not escaping** — parameters do that job now. `/api/galley`'s own statements stay in that endpoint: the write quota inside the `INSERT ... SELECT` is endpoint policy, not table access.
- `scripts/links-db.mjs`, `scripts/notes-db.mjs` — thin binders turning `{ local }` into a store, so every operator call site reads unchanged. The local-only guards on the destructive fixture helpers live here, because `--local` is a fact about which *database* a CLI was pointed at and the store modules do not know what a database is.
- `scripts/d1-store.mjs` — a D1-compatible façade over `wrangler d1 execute` (`prepare().bind().all()/.first()/.run()`), so one copy of the SQL runs on both paths.
- `src/lib/sql-literal.js` — `renderSql` / `sqlLiteral`: **the escaping boundary** for every statement run from the CLI, and the whole of it. Split out of the façade so `node --test` can reach it — the quiet failure is a placeholder/parameter mismatch, which slides every subsequent value one column left and which SQLite accepts. Unit-tested in `src/lib/sql-literal.test.js`.
- `src/lib/link-state.js` — `linkState(row, { pubDate, now })` → `live` / `expired` / `revoked` / `spent`, plus the extend headroom. Extracted from `preview-roster.mjs`'s `format()` so the CLI and the Desk cannot disagree about what "outstanding" means. Note that an **expired** link still reports headroom: `extendLink`'s `WHERE` never looks at the current `exp`, so a lapsed link can be wound forward on the URL the reviewer already holds. Unit-tested in `src/lib/link-state.test.js`.
- `src/lib/server.ts` — shared `/api/*` plumbing: `securityHeaders`, `getEnv()` / `tryGetEnv()`, `parseJson()`, `jsonOk()`, `jsonError()`, `methodNotAllowed()`. The single source of truth for server-endpoint conventions. `tryGetEnv()` is the fail-closed read — `cloudflare:workers` throws when touched outside the worker runtime, and swallowing that belongs here rather than in a try/catch at each call site.
- `src/env.d.ts` — types for Cloudflare runtime `Env` (`BUTTONDOWN_API_KEY`, `TURNSTILE_SECRET_KEY`, `PREVIEW_SIGNING_KEY`, `DB`, and the Access trio `ACCESS_TEAM_DOMAIN` / `ACCESS_AUD` / `ACCESS_JWKS_OVERRIDE`) and Astro `ImportMetaEnv` (`PUBLIC_TURNSTILE_SITE_KEY`). Also augments `App.Locals` with the preview signals and `admin`; **`undefined` must always mean denied** for every one of them. Declares `__BUILD_TIME__` as well — the only global Vite defines into the bundle, typed here because nothing else would tell a reader it exists.
- `src/content.config.ts` — Zod schema for blog post frontmatter (single source of truth for required/optional fields and tag validation).
- `src/content/blog/<slug>.mdx` — one file per post (or `<slug>/index.mdx` when colocating images).
- `src/lib/archive.js` — the archive as a *sequence*: `FIXTURE_SLUG`, `realPosts` (the list minus the fixture), `adjacentIn` (previous/next) and `latestIn` (what a surface features). Takes the already-sorted, newest-first array rather than fetching it, which is the whole point — `blog.ts` imports `astro:content`, so `node --test` cannot load it, and these decisions previously had no coverage but a live HTTP assertion. **`FIXTURE_SLUG` is declared here, once.** It used to be spelled twice (here and in `scripts/smoke/config.mjs`) with a `static.mjs` grep pinning the copies together; `config.mjs` runs under bare node and can import this module, so the drift check is gone. **The fixture is excluded from both functions and that is the point of them** — dated 2099 it is the newest post there is wherever scheduled posts are visible at all (a `*.workers.dev` preview host, `astro dev`), so a plain `posts[0]` made the home page's "From the Lexicon" block read "Scheduled-post fixture (not a real post)" on every preview deploy, and the newest real post's `Next →` pointed at the same thing. Production is unaffected either way, which is what made this invisible. Unit-tested in `src/lib/archive.test.js` against `{ id }` stubs — nothing here reads `data` — so the two ends, a post the query cannot see, and the fixture's exclusion are each stated exactly rather than inferred from whatever `src/content/blog` holds this month. **That independence is the reason the module exists.** The live check it replaced picked one subject, "the newest non-fixture post", and required a `.post-nav` on it; that silently assumed the newest real post is *published*, because `BlogPost.astro` drops previous/next on a draft — so scheduling an ordinary post turned smoke red with the invariant untouched. Worth knowing before re-tightening the live half: while any real draft is the newest non-fixture post, the fixture can only ever be *that* post's `Next →`, and that post renders no nav, so the exclusion is **unobservable over HTTP** in that state. `live-preview.mjs` therefore asserts only the wiring (at least one post still renders a nav; no post's nav names the fixture) and leaves the rule to `node --test`.
- `src/lib/blog.ts` — `getPublishedPosts`, `getAllTags`, `getPostsByTag`, `getTagCounts` (the topic index), `getAdjacentPosts` (previous/next), `getLatestPosts` (the post or posts a surface features), plus the `dateFormatter` / `isoDate` / `postReadingTime` helpers used by `BlogPostEntry.astro`. **`getAdjacentPosts` and `getLatestPosts` are one line each now** — the rule they used to hold lives in `src/lib/archive.js`, and these are the fetch in front of it. `static.mjs` asserts they still *call* it, the same shape as the `isPublished` call-site check. The single boundary between content source and rendering — a future D1 migration swaps only this module. `getPublishedPosts` also enforces scheduled publishing: in production (`import.meta.env.PROD`) it hides any post whose `pubDate` is in the future; in dev those posts stay visible for preview. Because index, tag, and post routes all flow through it, that one filter gates every surface (RSS included, via the on-demand feed). All three helpers take an optional `{ showScheduled }` — passed from `Astro.locals` so `*.workers.dev` preview deploys show drafts — defaulting to hidden so a call site that forgets it fails closed. The per-post signed-link unlock is deliberately *not* threaded through here; see "Previewing a scheduled post".
- `src/lib/edition.js` — `issue(now?)` → `{ volume, number, label, short }`, plus `toRoman` and an `editionLine` alias for the full label. **One derivation, from one fixed launch epoch (`EPOCH = { year: 2026, month: 4 }`), called once per render in `Base.astro`.** The August 2026 design review found `/blog` rendering `No. VII · July 2026` while home and the posts rendered `No. VIII · August 2026` — a masthead whose date went backwards as the reader clicked. Nothing rendered in a **page's chrome** may derive an issue from a page, a route, or a content date — that is the bug, and it is a bug because two live surfaces disagreed about what *today's* issue was. A **build-time artifact that dates itself** is the one exception, and there is exactly one: `scripts/make-post-og.mjs` prints `issue(pubDate).short` on a post's OG card. That is a different claim — the issue the post ran in, not the issue it is now — and it is the claim a periodical's archived piece actually makes. It also cannot drift, which is the property `make-og.mjs` omits an edition line to protect: `pubDate` is fixed, so the card regenerates identically forever, where `issue(now)` would move under it every month. Do not read that exception as licence to put a content date into `Base.astro`. The number counts **months since launch**, not the calendar month: the old rule had the two halves on different clocks (`No. XII` was December whether the periodical was one month old or nine, and the volume turned over on New Year's Day). Twelve issues to a volume, the volume turning on the anniversary. Plain JS, not TypeScript, for the usual reason — the failure here is a plausible wrong number, so it needs tests and tests need an importable module. Unit-tested in `src/lib/edition.test.js`, which pins the launch month, the 1..12 range, the volume rollover, and the UTC month boundary.
- `src/lib/tags.js` — `tagLabel(slug)` (title-cased for display, kebab slug stays in the URL — chips used to show `safe-streets` raw) and `RETIRED` / `retiredTarget(slug)`, the map from a tag the August 2026 consolidation dropped to where it goes now. Both jobs in one module because they are the same fact from two sides: what a topic is called, and what it used to be called. `src/pages/blog/tag/[tag].astro` checks `retiredTarget` **before** the membership test — a retired slug is by definition no longer in the live set — and 301s. Unit-tested in `src/lib/tags.test.js`, which also asserts every retired tag points at a slug some post actually carries (a map pointing at a 404 is worse than the 404 it replaced) and pins the working vocabulary against real frontmatter.
- `src/lib/identity.js` — `TAGLINE`, `SET_IN`, `BUILT_WITH`, `SITE_DESCRIPTION`: the sentences the site says about itself. Here because they are said in **two rendering engines that can import them** — `Base.astro` emits them as HTML on every page, `scripts/make-og.mjs` renders them into the SVG behind `public/og.png` — and a string spelled once per engine drifts. The OG card is the half that drifts *silently*: it is a manual `just og` step rather than a build step, and nothing here can read text out of a PNG. `SITE_DESCRIPTION` is derived from `TAGLINE` rather than written out, which removed two further copies inside `Base.astro` itself (`SITE_ALT` and the `description` default). **Stores plain text** — escaping belongs to the renderer, since Astro escapes its own `{}` expressions while the SVG needs `&amp;`; a pre-escaped string is wrong in the other engine. The two-tone wordmark and `mjrossi.com` are deliberately *not* here: they are shared markup shapes rather than shared sentences, so there is no value to lift. `scripts/smoke/static.mjs` asserts neither renderer spells either sentence itself, folding `&amp;` back to `&` first so the colophon's ampersand cannot hide a re-inlining. **The colophon has a third engine, and it cannot import** — `docs/buttondown-rss-template.md` is pasted by hand into Buttondown's dashboard, so it spells `SET_IN` and `BUILT_WITH` as literal markdown. That copy is pinned the *other* way round: smoke asserts the template still **matches** these constants, so editing one of them goes red until the template is updated and re-pasted. Rewriting a sentence here is therefore an operator step as well as a code change.
- `src/lib/now.js` — `NOW_UPDATED` (`YYYY-MM`) and `nowUpdatedLabel()`, the dateline under the home page's **Now** heading. A config value rather than a string in the markup, so updating the section is one obvious line and a malformed value fails the build instead of rendering `Updated undefined`. Formatted from the parts, never through `new Date('2026-08')`, which is midnight UTC and renders as the previous month west of Greenwich. Unit-tested in `src/lib/now.test.js`.
- `src/lib/readingTime.js` — word-count read time. Plain JS (was `.ts`) so `scripts/make-post-og.mjs` can import it under bare Node: the OG card prints the same read time the page does, and two implementations would drift the first time `WORDS_PER_MINUTE` moved.
- `src/layouts/BlogPost.astro` — post chrome (title, byline, tags, optional cover, back link).
- `src/pages/blog/index.astro`, `src/pages/blog/[...slug].astro`, `src/pages/blog/tag/[tag].astro`, `src/pages/blog/rss.xml.ts` — list, post, per-tag, and RSS routes.
- `src/styles/global.css` — all styles, imported once via `Base.astro`. Uses CSS custom properties.
- `astro.config.mjs` — Cloudflare adapter, MDX integration (for the blog), sitemap integration (**filtered through `isAdminPath`**, so the Desk's per-post URLs — one per scheduled draft — never reach a public file), Astro `Font` integration for Inter / Fraunces / Source Serif 4. Also `vite.define` for **`__BUILD_TIME__`**, the build's own clock inlined as a literal — see `make-post-og.mjs` below for the one question it answers. It is evaluated when Vite loads this config, which is the start of `astro build` and therefore *before* the generator runs; that ordering is what makes the set of advertised cards a subset of the set written, and it is the only reason the two can never disagree in the dangerous direction.
- `wrangler.jsonc` — Worker config; `ASSETS` binding points at `dist/client`. Carries the `vars` block holding the Cloudflare Access team domain and AUD tag that gate `/admin` — identifiers, not credentials, and shipped as placeholders that must be replaced before the Desk works. Also declares `SESSION` (KV). **`SESSION` is not a feature this site uses** — `@astrojs/cloudflare` injects it into the generated `dist/server/wrangler.json` whenever `config.session.driver` is unset, which is unconditional and has no clean off switch, so the binding exists on the deployed Worker either way. It is declared here so the resource is visible in the repo rather than only in generated output and the dashboard. `smoke.mjs` asserts `wrangler.jsonc` declares every binding the build emits, so a future adapter release that injects another one fails the build. The check is one-directional by design (generated ⊆ declared) — a binding declared here but dropped by the build is not flagged.
- `src/lib/schedule.js` — `isPublished(pubDate, now?)`, the scheduled-publishing predicate, plus `publicationTime` / `clampToPublication`, which are how a preview link's expiry gets capped at publication. Plain JS (like `csp.js`) so `node --test` can import it without `astro:content`. The clamp is minting policy and the worker never calls it, but it answers the same question as `isPublished` from the other side and the clamp is CLI-only — unit tests are the only coverage it can have. `publicationTime` rounds **up**, so the two comparisons hand over with neither a gap nor an overlap: at the publication second the link is already expired (`isLinkActive` is exclusive) and the post is already public (`isPublished` is inclusive). Unit-tested in `src/lib/schedule.test.js`; see "Scheduled publishing" under Blog.
- `src/lib/pubdate.js` — `coercePubDate(value)`, the frontmatter-date rule, used by `src/content.config.ts` and by `scripts/content.mjs` so the build and the minting scripts cannot disagree about when a post publishes. Rejects one shape and one only: a **quoted** timestamp with a time and no offset, which YAML would have read as UTC unquoted but `new Date()` reads as local. Unit-tested in `src/lib/pubdate.test.js`, which also pins js-yaml's own timestamp resolution. See "Scheduled publishing".
- `src/lib/preview.js` — the two scheduled-post preview unlocks: `isPreviewHost(hostname)` (`*.workers.dev` branch/version hosts → show drafts, but **not** the Worker's own production alias) and `signPreviewToken` / `verifyPreviewGrant` (signed, expiring, single-post links). Also exports `newLinkId` / `LINK_ID_RE` — every token carries a link id naming its row in `preview_links`, which is what makes it revocable — and `WORKER_NAME`, which must stay equal to `name` in `wrangler.jsonc` (smoke asserts it). `signPreviewToken` takes the same object `verifyPreviewGrant` returns, so minting and verifying stay symmetric. Deliberately **DB-free**: the allowlist lookup lives in `src/lib/preview-links.js`, so this one module still runs in the worker, under `node --test`, and in `scripts/preview-link.mjs` — the code that mints links is the code that verifies them. Unit-tested in `src/lib/preview.test.js`; see "Previewing a scheduled post".
- `src/lib/preview-links.js` — `isLinkActive(DB, id, now?)`, the `preview_links` allowlist lookup that makes a link revocable **and extendable**. Requires two things of the row: `revoked_at IS NULL`, and an `exp` still in the future. That second check is what makes the row's `exp` the expiry a request is actually judged against — the one `just preview-extend` moves without changing the URL — while the token's own signed `exp` becomes the immutable cap above it. See "Every link is revocable" for the clock-and-cap model. Called by `src/middleware.ts`, and plain JS rather than inline in it for one reason: middleware imports `astro:middleware`, so `node --test` cannot load it, and this was the only fail-closed branch in the feature with no persistent test — `return false` in a bare `catch` is one character from `return true`. Takes the store as an argument (duck-typed, so a test passes a three-line stub) rather than importing a binding, which is what keeps `preview.js` DB-free as well. Unit-tested in `src/lib/preview-links.test.js`, which covers the expiry boundary plus the two paths smoke cannot reach over HTTP: a missing `DB` binding and a store that throws.
- `scripts/preview-link.mjs` — mints a signed preview link (`npm run preview-link -- <slug> (--remote | --local) [--hours N] [--host URL] [--reviewer LABEL]`). Reads `PREVIEW_SIGNING_KEY` from the environment or `.dev.vars`; validates the slug against real content before signing. **Records the link in `preview_links` before printing the URL** — a link whose row failed to write would be refused on arrival, so a failed insert hands out nothing. Sets **both** expiries: `--hours` becomes the row's effective `exp`, and the token is signed with a ceiling `CEILING_HOURS` (30 days) out, which is the furthest `preview-extend` can later reach. The row's `exp` is additionally **clamped to the post's `pubDate`** — a link to a draft has nothing left to grant once the draft is public — while the signed ceiling is left alone, which is what leaves headroom when a date slips. An already-published post skips the clamp and mints as before, so the local galley trial loop still works on any post. Mint the window you actually mean — a short one costs nothing now that more time doesn't mean a new link. URL on stdout, metadata (link id, publication, ceiling, the revoke and extend commands) on stderr.
- `scripts/preview-extend.mjs` — moves a live link's expiry in place (`just preview-extend <slug> <id> (--remote | --local) [--hours N]`), or every live link for a post at once (`just preview-extend-all <slug>`, i.e. `--all`). **The URL does not change**, which is the entire point: nothing is re-sent and the reviewer never learns their link was about to lapse. `--hours` is a new window measured from *now*, so it shortens as readily as it extends, and it is **clamped to `pubDate`** rather than refused — asking for more time on a draft about to go public is reasonable, and the answer is "until it does". Extending a link on an **already-published** post is refused outright: there is no expiry left to move it to. `--all` is the command for "I pushed the date out"; it exits non-zero and names any link whose signature ceiling falls short of the new date, since that one has to be reminted. Refusals are specific by design — a no-op `UPDATE` looks identical for a link that never existed, one belonging to another post, one revoked, and one asking past its ceiling — so it reads the row back through `getLink` purely to say which. Unlike `preview-link`, **stdout stays empty**: there is no artifact to pipe, and printing the unchanged URL would invite re-sending it.
- `scripts/preview-roster.mjs` — lists and revokes preview links (`just preview-roster` / `just preview-roster-all` / `just preview-revoke`). The only inventory of issued links there is. `--all` lists every link across every post, grouped by post, because a link whose slug you have forgotten is otherwise unrevocable — the per-post scoping that matters in the worker doesn't apply to a CLI already authenticated as you. **Revoking stays per-post**, so a mistyped id can't withdraw another draft's link. Live rows also show `· extend to <date>` — their remaining headroom, which is the signature ceiling **or publication, whichever comes first**, since that is what `preview-extend` will honour — and the `expired` label is now the state the worker enforces, not a description. A link whose post has published reads `spent (published <date>)` and stops counting as live: nothing needs doing about it, but the roster's answer to "what is outstanding?" has to stay true. No admin endpoint, same rationale as `galley-pull.mjs`.
- `scripts/cli.mjs` — the prologue every operator command was writing for itself: `cli(tool)` returns `die` (stderr prefixed with the tool's own name, exit 1), `resolveDatabase` (the try/catch that turns `chooseDatabase`'s throw back into a `die`), and `requirePost` (the `resolvePostSource` guard), plus a standalone `relativeToCwd`. Bound once at the top of a script so every existing bare `die(...)` call site reads unchanged. Copies drift and this set already had: `preview-link`'s guard named both file shapes it probed, `galley-close`'s and `galley-reopen`'s said only "no post found" — the richer message is now what all four print, which matters for the post that has just gained a colocated image and moved between the two. **Argv parsing deliberately stays in each script.** The six flag loops look alike from a distance and are not alike up close: every one carries refusal messages written for that command's own mistake (`--hours 0` is a revoke wearing the wrong name; `--all` alongside a slug; a reviewer label that cannot be signed), and those messages are the most useful lines in the file. Nothing in this repo executes these scripts under test, so a parser general enough to keep them would drift silently.
- `scripts/database-target.mjs` — `chooseDatabase({ local, remote })`, `databaseLabel(local)`, and `databaseFlag(local)`. Every operator script that touches D1 (`preview-link`, `preview-roster`, `galley-pull`) requires an explicit `--remote` or `--local` and prints which one it used. There is **no default**: `--local` used to be opt-in on a production default, so forgetting it silently wrote a real row, and pointing a read at the wrong database answered "no links minted" / "no notes" for one that was never queried. Both mistakes are invisible at the time. `smoke.mjs` is exempt — not operator-facing, and local by construction.
- `scripts/d1.mjs` — `DB_NAME`, `d1Execute`, `d1Migrate`. The single place this repo shells out to `wrangler d1 execute`, and now only the transport under `scripts/d1-store.mjs` — the SQL itself moved to `src/lib/*-store.js`. Throws rather than exiting so each caller keeps its own `die()` prefix. Preserves three distinct failure messages that must not collapse into one: unreachable database, unparseable output, and output that parsed but is not the `[{ results: [...] }]` shape. The third throws rather than returning `[]` — a silent empty result from `d1Execute` would make `preview-roster` report "no links minted" for a table it never actually read, and that list is the only inventory of issued links there is.
- `src/lib/links-store.js` — the only owner of `preview_links` SQL (`recordLinks`, `revokeLinks`, `extendLink`, `extendLinks`, `getLink`, `listLinks`, `listAllLinks`, `clearLinks`). Runs against a duck-typed store, so the worker's binding and the CLI's wrangler façade execute one copy. Validates its own inputs (`SLUG_RE`, `LINK_ID_RE`, `Number.isInteger`) — as **domain validation**, giving a named error instead of a silent no-op, not as escaping; parameters do that, and `src/lib/sql-literal.js` is where the CLI half of the argument is made. `smoke.mjs` seeds fixtures through the same `recordLinks` production mints through, and runs `extendLink` end to end there too — it is the only place these statements execute under test, since the CLI path shells out to wrangler when called. **`extendLink` enforces the ceiling inside its own `UPDATE`** (`? <= max_exp`), not in the calling script: a read-then-write would be two round-trips with a window between them, and would move the one invariant stopping an extendable link from becoming a permanent one out of the module that owns the table. Same argument as the galley write quota being a single `INSERT ... SELECT`. `getLink` exists only to *explain* a refusal, never to gate one.
- `scripts/content.mjs` — `resolvePostSource(slug)`, the `<slug>.mdx` / `<slug>/index.mdx` probe shared by `preview-link.mjs` and `galley-pull.mjs`, plus `readPubDate(slug)` for the three commands that cap or report against publication (`preview-link`, `preview-extend`, `preview-roster`). `readPubDate` parses with **js-yaml and then `coercePubDate`** — the same two steps in the same order as Astro's loader and `src/content.config.ts`. That sharing is the point: a script and a build that disagreed about when a post publishes would mint links expiring on the wrong day, and for the quoted-timestamp case the disagreement would be a whole time zone wide. Same anti-drift rationale as `dev-vars.mjs`.
- **`js-yaml` is a direct dependency**, pinned to `4.3.0` to match astro's own range. It resolves today only because astro depends on it — the same hoisting accident documented for `@astrojs/markdown-remark` above — and `scripts/content.mjs` plus `src/lib/pubdate.test.js` both import it directly, so declaring it makes the resolution ours rather than a lockfile's.
- `scripts/dev-vars.mjs` — `readDevVar(name)`, the one `.dev.vars` parser shared by `preview-link.mjs` and `smoke.mjs`. Both sign preview tokens that the worker must then verify, so they have to agree byte-for-byte on quoting: if one strips surrounding quotes and the other doesn't, `PREVIEW_SIGNING_KEY="…"` makes smoke sign with a different key than wrangler injects, and the positive-path preview assertions fail locally while CI (which has no `.dev.vars`) passes. Same anti-drift rationale as `csp.js` / `security-headers.js`.
- `src/lib/security-headers.js` — `SECURITY_HEADERS`, the canonical non-CSP header set (HSTS, COOP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy). Imported by `src/middleware.ts` and `scripts/gen-headers.mjs` so the worker and the static `_headers` file can't drift. Same split-source rationale as `csp.js`.
- `src/middleware.ts` — applies `SECURITY_HEADERS` to **every** worker response (set-if-absent, so a route that chose a stricter value keeps it — `/api/*` sends `Referrer-Policy: no-referrer` and `Cache-Control: no-store`), then adds `Content-Security-Policy` and the default `Cache-Control: public, max-age=3600` to HTML responses only. Routes can override Cache-Control by setting it before middleware runs (e.g. prerendered `/404` emits `max-age=0` from Astro and middleware leaves it alone). `_headers` rules only apply to static asset responses served by the Cloudflare ASSETS binding; on-demand routes bypass that file, so middleware is the single source of truth for their headers. The all-responses scope matters for `/blog/rss.xml`, which went on-demand for scheduled publishing and would otherwise ship with no security headers at all. Middleware is also **the gate on `/admin`**, the Desk: it verifies the Cloudflare Access JWT (`src/lib/access.js`) before the route runs and returns 404 — not 403 — on any failure, so an unauthorised request never reaches a page that lists every draft. Path matching is `isAdminPath`, shared with the sitemap filter. Middleware also resolves the two scheduled-post preview unlocks *before* the route runs, handing them to routes as `locals.showScheduled` / `locals.previewSlug` / `locals.previewReviewer`. For a signed link that means two checks, not one: the signature, and then a lookup in the `preview_links` allowlist that makes the link revocable (`isLinkActive` from `src/lib/preview-links.js`, fail-closed on a missing binding, a D1 error, a missing row, or a revoked one). Both happen only when a `?preview=` token is present, so the normal request path does no HMAC work and touches no database. When either unlock is active — **or the request is for the Desk** — middleware **overrides** `Cache-Control` to `no-store` and sets `X-Robots-Tag: noindex, nofollow`. That override is the single exception to the set-if-absent rule above, because the values it replaces (`max-age=3600`, and the RSS route's own header) are exactly what would cache a draft. The Desk is in that set for a stronger version of the same reason: a preview link exposes one draft, `/admin` exposes the whole inventory, so a cached copy at the edge would be all of it in shared storage.
- `dist/client/_headers` — **generated**, not checked in. `scripts/gen-headers.mjs` writes it during `npm run build` from `src/lib/csp.js` + `src/lib/security-headers.js`, so the static-asset header set can't drift from what middleware applies to worker responses. Applies only to assets served by the Cloudflare ASSETS binding.
- `public/scripts/newsletter.js` — the client half of one of the two JS carve-outs. Served as a static asset (not bundled by Astro) so it loads as an external module from `/scripts/newsletter.js` and works under the strict `script-src 'self'` CSP. Imported only by `src/components/Subscribe.astro` — which now renders on the blog index *and* at the foot of every published post, so this ships on both.
- `public/scripts/galley.js` — the other carve-out. The editorial review client: selection → anchored note, and notes → markers. Same static-asset rationale. Loaded only by `src/components/GalleyMargin.astro`, which itself renders only on a signed review link, so this can never reach a publicly cacheable page. See "The galley".
- `public/scripts/galley-quote.js` — **both directions of the galley's quote anchor**, and they live together because they are inverses: `anchorSelection` (a selection → the quote, prefix and suffix a note stores) and `findQuote` (a stored quote → the exact characters to mark), plus `collapse`, `locateQuote`, `collapsedOffsetOf` and `rawOffsetOf`. Imported by `galley.js` at runtime (which is why it is served rather than living in `src/lib/`), and **DOM-free** — every function works in offsets over the block's text nodes passed as plain strings, so `node --test` reaches every case. Split out on the same argument as `galley-relocate.js`: a regression here is silent in both directions, since a mis-mapped offset marks the wrong words while looking entirely deliberate, or files a note describing prose the reviewer never selected. **The write side is the more important half** — a bad marker is wrong until the page reloads, a bad anchor is in D1 permanently and `galley-pull.mjs` relocates notes by it months later. Unit-tested in `src/lib/galley-quote.test.js`, which **round-trips the two directions against each other**; it lives under `src/` because `npm test` globs it there, and because a test file next to this one would be served to the public.
- `scripts/galley-preview.mjs` — `just galley-preview`: the galley margin rendered against fixtures on `127.0.0.1:8790`, with no build, no worker and no database. The markers are the one part of this repo whose correctness is a *rendering* question, and neither `npm test` nor `smoke.mjs` can see a pixel — the highlighter-pen gradient bug (see "Every note gets exactly one marker") was invisible to both and obvious here. Reads its CSS out of `GalleyMargin.astro` and `global.css` and serves the real `/scripts/galley.js`, so **nothing in it is a fixture copy of production code**; only the prose and a `fetch` stub standing in for `/api/galley` are fake. The stub accepts POSTs too, so the composer works. **`--stale` serves a page one revision behind the stub**, which is the only way to render the page-level staleness gate — without it that gate is unreachable here and deleting it looks identical (see "The margin never points at the wrong passage"). `--shot FILE` writes a PNG if a headless Chrome happens to be installed — not a dependency, and must not become one. Asserts nothing and CI never runs it: it renders something a human judges, like `scripts/make-og.mjs`.
- `src/lib/remark-source-anchors.js` — remark plugin stamping `data-src="<start>-<end>"` (MDX source lines) on every commentable block. Registered in `astro.config.mjs` under `markdown.remarkPlugins`. The anchoring half of the galley. **This is why `@astrojs/markdown-remark` is a direct dependency, pinned exact.** Sätteri is Astro's default Markdown processor and doesn't run remark plugins; setting `markdown.remarkPlugins` makes Astro swap the pipeline back to `unified()`, which it imports from `@astrojs/markdown-remark` — a package it declares only as an *optional peer*. It used to resolve anyway because npm hoisted `@astrojs/mdx`'s copy to the top level; a lockfile regeneration that nested it instead failed the build outright (`…is no longer installed by default now that Sätteri is the default Markdown processor`). Declaring it here makes the resolution ours rather than a hoisting accident. The pin must equal astro's `peerDependencies` entry — astro pins it exact and moves it on patch releases, so bump the two together.
- `src/lib/galley.js` — note validation + `sha256Hex`, shared by the write endpoint and the pull script. Plain JS, same rationale as `csp.js`.
- `src/lib/galley-relocate.js` — `unmark` / `fold` / `createLocator`, plus the fenced-and-blockquoted emitters for reviewer text. Split out of `galley-pull.mjs` because that script parses argv and shells out to wrangler at import time, so none of this was reachable from `node --test` — and it is the least obvious code in the feature. Unit-tested in `src/lib/galley-relocate.test.js`.
- `src/lib/post-source.ts` — `SOURCE_BY_SLUG` (raw `.mdx` by slug) and `revisionOf(slug)`, the SHA-256 of the whole file. Extracted from `api/galley.ts` when `BlogPost.astro` came to need the *identical* hash: the layout stamps the rendered page with it and the endpoint refuses a note that echoes a different one, so two definitions would refuse every write. Same anti-drift rationale as `scripts/content.mjs` on the CLI side.
- `src/pages/api/galley.ts` — `GET`/`POST` galley notes. Authorisation comes entirely from `Astro.locals` (middleware has already verified the token); both methods require `previewReviewer`. `GET` returns **open notes only** plus the closed ones separately for the "addressed" disclosure, flags each note `stale` when its `revision_hash` is not the current one, and reports the current `revision` so the client can tell its whole page is behind. `POST` refuses a note whose echoed `revision` is not the current source (`409 stale_page`) — see "A note is refused if its page has moved".
- `src/components/GalleyMargin.astro` — review chrome (bar, notes panel, composer). Owns its own styles, like `Subscribe.astro` — but in an **`is:inline`** block, which is specifically *not* scoped and is load-bearing in both directions. See "The CSS does not inherit that gate for free" under The galley.
- `scripts/galley-pull.mjs` — pulls notes into `docs/galley/<slug>.md` via `wrangler d1 execute`. No admin endpoint exists, because wrangler already authenticates the operator. **Open notes only** unless `--all`, so a round you have closed stops reappearing. **Prints every note's id**, which is what makes the file a manifest: `galley-close` closes exactly the ids it finds there. Keeps the I/O only — argv, the `.mdx` read, the D1 query, the write; everything deciding what the document *says* is `src/lib/galley-render.js`.
- `src/lib/galley-render.js` — the pulled review file itself: `renderReviewFile`, plus `groupByAnchor`, `resolveGroup`, `excerptAt`, `contextHint`, `isoDay`, `sectionMap`, `collapseDuplicates`, and `pushNoteContent` (which belongs with the other reviewer-text emitters, not in a script). Split out of `galley-pull.mjs` on the same argument as `galley-relocate.js` and `galley-manifest.js` — that script is unimportable under `node --test` — and this is where the pull's quiet failures live. **A group claims a relocation only when every quoted note agrees**: notes share an anchor whenever they were filed against the same block but can quote different sentences within it, so the wrong rule prints `## Line 42-47 — now line 88` over a note that was never about line 88. And **an unchanged file's stored anchor beats a relocation**, or the excerpt under a heading comes from elsewhere entirely. Neither surfaces as an error. `resolveGroup` returns a Map rather than writing `currentLine` onto each row — those rows are the caller's, straight from D1. `pulledAt` is a parameter so the output is a function of its inputs. Unit-tested in `src/lib/galley-render.test.js`, which also pins the manifest round-trip (every id rendered is an id `galley-close` will find) and the three ways reviewer prose could otherwise restructure a document whose headings are how notes get attributed to passages. See "What the pulled file tells you" for the section labels, the summary, and the two collapsing rules.
- `src/lib/notes-store.js` — the only owner of `galley_notes` SQL (`closeNotes`, `reopenNote`, `listNotes`, `countOpenNotesBySlug`, `seedNotes`, `clearNotes`). Same shape and same argument as `links-store.js` one table over. The exception is `src/pages/api/galley.ts`, which keeps its own statements: the write quota inside its `INSERT ... SELECT` and the open/closed read ceilings are endpoint policy — a bound on a leaked review link — rather than table access, and moving them here would put a decision about `/api/galley` in a module the CLI imports. `noteIdsInFile` stays in `scripts/notes-db.mjs`, since it is a file read rather than a query; the scan it wraps is `src/lib/galley-manifest.js`. Smoke seeds and closes through these functions because running the SQL needs a migrated local database.
- `src/lib/galley-manifest.js` — `noteIdsInMarkdown` and `NOTE_ID_RE`: reading a pulled review file back as the list of notes a close should touch. **This is the function that decides what `just galley-close` retires**, so it reads only the meta lines `galley-pull.mjs` writes — anchored at both ends, skipping blockquotes and fenced blocks. A body-wide search for a backticked UUID meant a reviewer quoting a colleague's note id closed that colleague's note, silently; editors are invited collaborators so this was never an attack surface, but it made the file stop meaning what the close command claims it means. Split out of `notes-db.mjs` so `node --test` can reach it (`galley-manifest.test.js`), on the same argument as `galley-relocate.js`: a regression here is silent in both directions — it closes the wrong set, or nothing, and reports success either way.
- `scripts/galley-close.mjs` — ends a review round (`just galley-close <slug> (--remote|--local) [--note ID] [--from PATH]`). Reads `docs/galley/<slug>.md` back and closes the note ids listed there; refuses with "pull first" when the file is absent. Reports how many notes it left open **and who filed them** — the concurrent-reviewer signal, and the reason this reads a file instead of selecting on drift. Run it *after* the revision merges. stdout stays empty.
- `scripts/galley-reopen.mjs` — the undo (`just galley-reopen <slug> --note <id>`). One note at a time by design: closing is routine, re-opening is a correction, and a correction should make you name what you mean. Explains a refusal by reading the row back, like `preview-extend.mjs`.
- `migrations/0003_galley_note_closure.sql` — adds `galley_notes.closed_at` (epoch MS, NULL = open) and **drops `status`**, the constant column `0001` reserved for this workflow. One fact, one column, the same shape as `preview_links.revoked_at`. **Apply it and deploy in one sitting — there is a window between them and neither order closes it.** Migration-first breaks *writes* until the deploy lands (the currently-deployed worker doesn't select `status` but it does INSERT it, so a note filed in the gap fails on the missing column); worker-first breaks *reads* instead, since the new `GET` and `galley-pull.mjs` both select `closed_at`. Migration-first is the one to take — a refused write is one reviewer retrying, a broken read is the margin down for everyone — but don't start a review round across it. The file's own header carries the full argument, including the expand/contract split that would remove the window and why it wasn't taken.
- `migrations/0001_initial.sql` — the original D1 schema: `preview_links` (who may see a draft, and who may comment) and `galley_notes` (what they said). Frozen — it is applied in production, and a migration is frozen the moment it is applied anywhere real. Apply the directory with `wrangler d1 migrations apply mjrossi-galley --local|--remote`.
- `migrations/0002_preview_link_ceiling.sql` — adds `preview_links.max_exp`, the signed cap that makes a link extendable. `NOT NULL DEFAULT 0`, so there is no "row without a cap" state to reason about anywhere: the default is required to add a `NOT NULL` column at all, and it is also the fail-closed value — a ceiling already in the past makes `exp <= max_exp` false, so `extendLink` refuses the row rather than moving it past a signature that would never honour the result. **The worker does not need this column**; it enforces the cap from the token and the expiry from `exp`, both of which predate this migration. Minting does need it, so apply it before the next `just preview-link`.
- `public/.assetsignore` — keeps worker artifacts out of the static asset binding.
- `scripts/smoke.mjs` — post-build smoke test. Checks static artifacts in `dist/client/` (CSS tokens, assets) and then spins up `wrangler dev` to hit every on-demand route. Run via `npm run smoke`. **The entry file is the run sequence and nothing else** — ~120 lines listing the phases in the order they must happen, with the assertions themselves in `scripts/smoke/`. That ordering is the part worth reading before changing anything: the D1 fixtures are seeded *before* the spawn because `wrangler dev` reads the persisted SQLite once at startup and never flushes back, the static checks run first so their failures survive a runtime that never comes up, and the write-quota flood runs last in its phase because it fills the hour's allowance.
- `scripts/smoke/*.mjs` — the assertions, split by what they can be run against:

  - `wrangler.mjs` — the `WORKER_NAME` ↔ `wrangler.jsonc` pairing and the binding-drift walk against the generated config.
  - `fixtures.mjs` — the `preview_links` and `galley_notes` fixture tables (id, row and reason on one line each), migrate/clear/seed, and the `extendLink` and `closeNotes`/`reopenNote` round-trips. The only place `links-db.mjs`'s and `notes-db.mjs`'s SQL executes under test. The note fixtures cover the three states a second review round can find — open-and-current, open-but-stale under a *second* reviewer, and closed — because every note the live matrix writes is open and current by construction, so without them a dropped `closed_at` filter or `stale` flag leaves the suite green.

Two exported phases because the preview matrices run between them.

Also `conflictingDevVars`, which is why `smoke.mjs` refuses to start when `.dev.vars` would shadow it — wrangler prefers `.dev.vars` over `--var`, and unlike `PREVIEW_SIGNING_KEY` smoke cannot adopt the developer's value, because the matching private key is not in the file.

The negative cases fail independently on purpose. The `desk-` HTML greps here are only half the leak check — see `static.mjs` for the CSS-bundle half.
- `scripts/make-noise.mjs`, `scripts/make-og.mjs` — one-off regenerators for `public/noise.png` and `public/og.png`. **The site-level card states identity only — never a fact about the present.** Social scrapers cache by image URL and effectively never re-fetch, so a card asserting where I live is wrong the moment that moves *and* the correction cannot reach the caches already holding it. That is the general rule the missing edition line was only the first case of: the card read "Brooklyn, New York" for months after the masthead said Lisbon, because this is a manual `just og` step rather than a build step and nothing compared the two. `make-post-og.mjs` may carry a date and a read time because those are facts about the *post*, pinned to a `pubDate` that never moves. `scripts/smoke/static.mjs` greps the generator for the regression, since nothing here can read text out of a PNG. Bump the `?v=` on `Base.astro`'s `ogImage` default whenever the card changes — the filename stays put, so a scraper that strips the query still lands on the current card.
- `scripts/make-post-og.mjs` — **runs on every `npm run build`**, after `astro build`, writing one 1200×630 card per post into `dist/client/og/<slug>.png`. Not a one-off like the two above: a post without a card would fall back to the generic image silently, so the generator enumerates the content directory and cannot rot. **Published posts only** — a card carries the post's title and `/og/<slug>.png` is a guessable URL, so generating one for a scheduled draft would hand that draft's title to anyone who guessed the slug (cover images get away with being built ahead because `astro:assets` hash-names them). A post therefore uses `/og.png` until the deploy that follows its publication, which step 5 of the authoring workflow produces anyway.

  **The layout asks the build's clock, not the request's, and the two are not interchangeable.** `BlogPost.astro` advertises a card when `isPublished(pubDate, __BUILD_TIME__)` — not when the post is published *now*. A post goes live by its `pubDate` passing with no deploy behind it, which is the whole scheduled-publishing mechanism; gate the `og:image` on the request's clock and that post starts advertising an `/og/<slug>.png` nobody generated, 404ing for every scraper during exactly the manual-syndication window the card exists for. Nothing else can see this: at build time the two agree by construction, so the built HTML is identical and every artifact check passes — the divergence opens hours later, in production. Three things pin it, and all three are needed because each is satisfied by a build that emitted no cards at all: a source grep on the gate (`scripts/smoke/static.mjs`), the file on disk plus the fixture's card being **absent** (same file), and the worker actually serving it (`live-site.mjs`, which is the ASSETS-binding half rather than the generator's). Renders SVG through **sharp** rather than Satori in the worker: sharp already ships with astro, so this costs a build step and nothing at runtime, whereas Satori plus a WASM rasteriser plus embedded font binaries is a large addition to a worker whose point is being small. Title width is *estimated*, not measured (0.58em/char with headroom, stepping the size down a ladder until it fits) — the estimate errs generous on purpose, because being wrong the other way runs the last word off the card.
- **`sharp` is a direct dependency**, pinned to `0.35.2`. It resolves today only because astro depends on it (astro's own image service) — the same hoisting accident documented for `js-yaml` and `@astrojs/markdown-remark` — and `scripts/make-post-og.mjs` imports it directly, so declaring it makes the resolution ours.
- **`typescript` is a direct dependency**, the only `devDependency` besides wrangler, pinned to `^6.0.3` to match astro's own range. It is the one dependency here that never resolved by accident: astro declares typescript in its *own* `devDependencies`, so unlike the `js-yaml` / `sharp` / `@astrojs/markdown-remark` hoisting cases above it was never installed transitively at all. **Nothing in this repo runs `tsc`** — it is here as a *library*. `mdx-analyzer`, the language server for `.mdx` posts, is handed a `tsdk` path by nvim-lspconfig's `get_typescript_server_path`, which walks up from the project root looking for `node_modules/typescript` and returns `''` when it finds none; the server then refuses to start with `Can't find typescript.js or tsserverlibrary.js in ""`. That failure is **editor-only and invisible to CI** — `npm run build`, `npm test` and smoke all pass without it, which is why it went unnoticed until someone opened a post in an editor configured for MDX. It stays in `package.json` rather than `mise.toml` for the same reason wrangler does (see "How mise and wrangler relate"): that lookup only ever searches `node_modules`, so a mise-managed copy would be invisible to the one consumer it exists for. `astro check` would resolve it the same way, if it is ever added to the build.
- `.github/workflows/` — `build.yml` (build + smoke), `lighthouse.yml` (audits **production only** after a `main` deploy; pass/fail gate, no PR comment).
