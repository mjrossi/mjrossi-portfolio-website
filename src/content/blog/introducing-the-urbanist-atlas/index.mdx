## A long time ago, in a Brooklyn brownstone far, far away...

The year: 2019. I had just relocated to New York City from Chicago. I needed to find local groups and get plugged into the advocacy space. Some searching later, I found a few — enough to get involved. This sparked an idea that I told a friend: "what if we built a website, where one could just enter their zip code, and get a list of local advocacy orgs?"

Well, it took until 2026, but that solution now exists.

## Introducing...The Urbanist Atlas

The Urbanist Atlas exists for one reason: when someone moves to a new city, or wakes up one morning in the place they've lived their entire life angry about a dangerous intersection three blocks from home that has never been fixed, they should be able to find the people already organizing for better streets and better transit nearby, in under a minute.

The site is live at [urbanistatlas.com](https://urbanistatlas.com).

## Core Principles

I'll likely write up more detail on the various aspects of this project throughout the coming weeks, but before I get into the details, this project is intended to be my small contribution to my fellow advocates in the US and Canada, many of whom fight tirelessly, day after day, in political and social headwinds that do not often favor this particular type of urban development. I'm releasing the full codebase as open source, and the [About](https://urbanistatlas.com/about) page lists all of our core principles.

I want this to be extended upon, with organizers, researchers, advocates (current and future) being able to find the groups where they are. There is a submission process for new organizations, or passing along corrections, so we as a community can keep the database as fresh as possible.

## Tech Stack

For the developers in the audience, here's how it's built. The Urbanist Atlas repository on [Github](https://github.com/mjrossi/urbanist-atlas) is a monorepo, split into two components:

* API — A Go service, with HTTP handling via the chi router, deployed to Fly.io. It is a stateless application: the api/seed/ TOML/CSV bundle is baked into the image and loaded into an in-memory FileStore at boot. It hosts the public JSON API at /api/v1. For now, this is only accessible by the WEB component, but the ultimate goal later is to allow registration of API keys so anyone can integrate with this library easily.

* WEB — Built in React + Vite SPA, and deployed to Cloudflare Workers + Pages (Static Assets). It consumes the JSON API to power all of the data.

More information is available in the repository and the site itself.

## What's next?

For now, the goal is to get the word out, see how the API and site performs at scale, and continue to curate the database to expand coverage across the US and Canada. Eventually, the API will be opened up for consumption outside of just the web component. Finally, I'd love to see support for more countries around the world -- the [region graph](https://github.com/mjrossi/urbanist-atlas/blob/main/docs/region-graph.md) that I designed is intended to be extremely flexible and handle a wide assortment of regions, and all the various flavors of edge cases.

I'm thrilled to see this project come to life, and look forward to continued evolution as more folks get their hands on it. We welcome submissions to grow and correct the database. If you're a developer interested in early API access or contributing to the repo, reach out. And of course, anyone can contact me with questions, feedback, or comments.

Enjoy the Urbanist Atlas: where you can find the people fighting for better streets where you live.
